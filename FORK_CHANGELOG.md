# ZXMAK2 Fork — changelog

Краткая хронология ZX-Evo BaseConf fork. Полные технические протоколы,
результаты probe и пользовательские наблюдения находятся в
`PROJECT_JOURNAL.md`; текущий план соответствия — в `BASECONF_AUDIT_B32.md`.

Статус runtime указывается только там, где пользователь действительно провёл
проверку. Успешная сборка или compiled-probe не заменяет runtime-приёмку.

## 2026-09-12—14 — исходная база до B01

- Исследованы прежние ветки ATM Turbo/ZX-Evo, Quick Boot, Kempston mouse,
  ввод, SD и переключение образов.
- Рабочей основой выбран v13; незавершённые эксперименты предыдущих версий не
  переносились пакетом.
- Текущая работа окончательно ограничена ZX-Evo BaseConf; ATM Turbo, TSConf и
  Scorpion не смешиваются с этим циклом.

## 2026-09-15 — B01–B16

- **B01:** чтение клавиатуры и tape-in через документированные `xxFE/xxF6`.
- **B02:** точное декодирование записи border вместо общего чётного порта.
- **B03:** исправлено чтение Z80 SD-портов `xx77/xx57`.
- **B04:** уточнено декодирование beeper; полный tape mux оставлен отдельным
  этапом.
- **B05:** Covox `xxFB` доступен согласно BaseConf и в DOS/Shadow.
- **B06:** исправлен порядок расширенных банков 7FFD для 4-МБ памяти.
- **B07:** добавлены write-protection masks. Первая проверка была отклонена из-за
  ошибки настройки probe; окончательный **B07-R1 19:33:01** принят после полной
  исправленной compiled-проверки.
- **B08:** приведено к документации декодирование CPU control ports.
- **B09:** переключение частоты перенесено на шинную модель CPU.
- **B10:** введена общая временная база 28 МГц.
- **B11:** реализованы WAIT свободной DRAM и буфер чтения.
- **B12:** добавлена арбитрация DRAM между CPU и видео.
- **B13:** введён бюджет WAIT внешних I/O-портов.
- **B14:** частота CPU фиксируется на границе `RFSH`.
- **B15:** создана общая таблица raster-профилей.
- **B16:** реализован базовый протокол AVR `RDCFG`.

## 2026-09-16 — B17

- **B17-R1:** восстановлена сборка и добавлено устойчивое управление raster

## 2026-09-17 — B18–B20

- **B18:** диагностический индикатор raster; использован для runtime-сверки.
- **B19:** зафиксирован официальный паспорт семи renderer-путей BaseConf r1364
  в `BASECONF_VIDEO_MODES_B19.md`.
- **B20:** объединены raster timing, picture window, border и INT-основа.
  Пользовательская runtime-проверка принята в оговорённом объёме.

## 2026-09-18 — B21–B29

- **B21/B21-R1:** создан bootable video test menu, затем исправлен загрузчик
  `BCVIDTEST.TRD`.
- **B22/B22-R1:** первые pattern-suite отклонены runtime-проверкой.
- **B22-R2:** исправлены BOOT/pager и format-aware patterns; загрузка принята.
- **B23:** исправлены общая BaseConf-палитра и ATM 640 test artifacts;
  runtime принят.
- **B24:** улучшены старт и underrun DirectSound, но пользовательская проверка
  выявила оставшиеся артефакты и этап был отклонён.
- **B25+B26:** по измерениям настроен финальный RejectDC. Старт/тишина и наводки
  дисковода приняты; различие с UnrealSpeccy оказалось сравнением разных
  звуковых устройств и было снято пользователем.
- **B27:** исключён старый runtime-профиль из проверки ZX-Evo; runtime принят.
- **B28/B28-R2/B28-R3:** диагностированы разные пути прямого SCL и SD→Ramdisk,
  включая M1 trace страницы `#FE`.
- **B29:** virtual FDD приведён к BaseConf RTL. Rage из SD/Ramdisk запускается
  коротким Enter; NedoOS и прямой SCL сохранены. Runtime принят.

## 2026-09-19 — B30–B36

- **B30:** исправлена фаза 256×192 относительно INT; border/multicolor
  пользователь подтвердил как правильные.
- **B31:** virtual-FDD trap запрещён при официальном `!atm_pen2` gate. NedoOS,
  Rage, Bad Apple и B30 video пользователь проверил успешно.
- **B32:** выполнен полный статический аудит BaseConf r1364; зафиксированы
  открытые расхождения и неизменяемый порядок последующих этапов.
- **B33:** реализовано точное декодирование Nemo IDE.
- **B33-R1:** добавлены выбор, сохранение и eject HDD-образа; HDD/FAT/files
  подтверждены runtime. Зафиксирована промежуточная стабильная точка и
  опубликован prerelease Alpha 0.1.
- **B34:** повторная замена SD/HDD переведена на безопасный media lifecycle с
  cold power-cycle. Пользователь подтвердил SD↔HDD, чтение обоих источников и
  отсутствие прежнего зависания. Опубликован
  [Alpha 0.2](https://github.com/Moro44444444/ZXMAK2-Fork/releases/tag/v0.2-alpha).
- **B35:** завершены документированные регистры `#BF/#BD/#BE`, ROM write gate,
  breakpoint address latches и readback. Общий runtime regression smoke принят;
  новые служебные latch отдельно приложением не тестировались.
- **B36:** реализованы interrupt acknowledge, внешний WAIT hook, кадровый и
  breakpoint-NMI, переход `#0066`→RAM `#FF` и задержанный выход через `#BE`.
  Пользователь не обнаружил видимых регрессий; сами INT/NMI-переходы имеют
  compiled-probe, но не отдельную runtime-приёмку.

## 2026-09-20 — B37

- **B37:** декодирование AVR/gluclock `F7` и COM `EF` приведено к официальным
  уравнениям r1364; добавлены документированные регистры `#F8EF..#FFEF`,
  внешний WAIT с паузой активного INT и трёхтактовый DOS settling stall.
  Release и полный актуальный regression suite проходят; пользовательская
  runtime-приёмка ожидается.

## 2026-09-21 — B38

- **B38:** добавлен документированный восьмибитный Kempston joystick на
  точном младшем байте `#1F`; фактический порядок обработчиков сохраняет
  владение VG93 пересекающимся `#1F` в Shadow/DOS.
- Tape-in подключён к документированным чтениям `xxFE/xxF6` по D6 без
  ошибочного loopback из FE-out. Отдельный PentEvo beeper реализует
  сохраняемый AVR D3 mux между FE.D4 beeper и FE.D3 tape-out; Num Lock следует
  официальной функции AVR `func_beeper()`.
- Старые пятибитные Kempston-профили, AY, Covox, DirectSound и RejectDC не
  изменены. Полный актуальный regression suite проходит; пользовательская
  runtime-приёмка B38 ожидается.

## Следующий утверждённый порядок

1. **B39:** ULAplus и официальная палитра 4:4:4.
2. **B40:** contention, floating bus, raster/INT/video phase, golden-векторы;
   VG93 trace только при подтверждённой ошибке.
3. После полного встроенного BaseConf — два ZX-BUS слота и документированная
   периферия, затем отдельный CD/ATAPI этап.

## Активный backlog

- SD Card: New/Eject, сохранение подключённого образа и корректное поведение
  первого подключения без потери состояния.
- CD/DVD: IDE/ATAPI с образом или host-приводом, только по документации.
- Hotkeys: `F12` и `Alt+Ctrl+End` для Warm Reset, `Ctrl+F12` для безопасного
  CMOS reset с подтверждением и backup.
- Автоматическая HDD-загрузка NedoOS — после стабилизации контроллера.
- Диагностика Rage на конкретном 4-ГБ SDHC-образе: SCL побайтно совпадает с
  рабочим, поэтому проверяется SDHC/sector-addressing и импорт RAM-диска.
- Публичные portable-релизы очищаются от пользовательских `.cmos`, `.vmide`,
  media images, логов, PDB и абсолютных путей; чистый профиль, ROM/PAK,
  зависимости, документация и лицензия сохраняются.
